# История гильдии

## Назначение

Раздел **«История гильдии»** — единый неизменяемый журнал действий внутри гильдии. Он помогает лидеру и участникам восстановить последовательность изменений и понять, кто выполнил действие.

Страница доступна по маршруту:

```text
/guilds/{guild}/activity
```

Ссылка расположена последней в меню выбранной гильдии. Просмотр разрешён только участникам этой гильдии; проверка выполняется middleware `guild.member`.

## Что логируется

| Категория | Примеры действий |
|-----------|------------------|
| `auction` | создание и закрытие лота, ставка |
| `roulette` | изменение участников, самостоятельная запись и выход, открытие набора, режим выбывания, коэффициенты ДКП, запуск вращения |
| `storage` | создание, изменение и удаление тиров и предметов, выдача и отмена выдачи |
| `members` | вступление, самостоятельный выход, исключение, смена роли и изменение данных участника |
| `access` | создание и удаление ролей, изменение набора прав роли |
| `guild` | изменение названия, описания, устава, логотипа, сервера, набора, Discord-настроек и других параметров |
| `journal` | создание, изменение и удаление постов и комментариев гильдии |
| `events` | действия с календарём, отказ от участия и история событий |

Для записи используются Eloquent observers. Действия, которые не изменяют отдельную Eloquent-модель, записываются явно в соответствующем Action. Например, синхронизация прав роли и действия Socket.IO рулетки.

## Состав записи

Таблица `guild_activity_logs` хранит:

- `guild_id` — гильдия;
- `actor_user_id` — пользователь-инициатор, если он известен;
- `actor_name` — снимок имени пользователя на момент действия;
- `category` и `action` — машинные идентификаторы раздела и действия;
- `subject_type`, `subject_id`, `subject_name` — связанный объект;
- `description` — готовое описание для интерфейса;
- `old_values` и `new_values` — безопасные изменённые значения;
- `metadata` — дополнительный контекст;
- `created_at` — время действия.

Пароли, Discord webhook URL, полные тексты постов, описаний и другие объёмные или чувствительные поля в снимки изменений не попадают. При удалении пользователя ссылка `actor_user_id` очищается, а `actor_name` остаётся.

## API

```http
GET /api/v1/guilds/{guild}/activity
```

Параметры запроса:

| Параметр | Назначение |
|----------|------------|
| `created_from` | начало диапазона дат включительно, `YYYY-MM-DD` |
| `created_to` | конец диапазона дат включительно, `YYYY-MM-DD` |
| `category` | одна из категорий журнала |
| `action` | точный машинный идентификатор действия |
| `actor_name` | поиск по имени инициатора |
| `search` | поиск по описанию и названию объекта |
| `page` | страница результата |

Фильтры backend реализованы классом `GuildActivityLogFilter` и применяются через trait `HasFilter`. Сортировка всегда идёт от новых записей к старым. Размер страницы фиксирован: **50 записей**.

Ответ содержит массив `data` и объект пагинации `meta` с полями `current_page`, `last_page`, `per_page` и `total`.

## Интерфейс

Панель фильтров содержит:

- поиск по описанию или объекту;
- имя инициатора;
- категорию;
- единый `DateRangePicker`, используемый также во вкладке логов конст-пати;
- кнопку сброса в виде крестика. Кнопка недоступна, пока фильтры не заданы.

Страница использует общий `contentShell`. На desktop он резервирует справа колонку шириной 300 px для рекламного блока, как на странице конст-пати; на узких экранах журнал занимает всю ширину.

## Рулетка и Socket.IO

Клиент получает краткоживущий зашифрованный токен через:

```http
POST /api/v1/guilds/{guild}/roulette/socket-token
```

Socket-сервер проверяет токен через backend, связывает соединение с пользователем и гильдией и разрешает управляющие действия только при наличии права `upravlenie-ruletkoi`. Принятые изменения отправляются во внутренний audit endpoint и записываются в историю гильдии.

Для socket-сервера используются переменные `ROULETTE_AUTH_URL`, `ROULETTE_AUDIT_URL` и общий секрет `SOCKET_SERVER_INTERNAL_TOKEN`.

## Развёртывание и проверка

После обновления необходимо выполнить миграции и перезапустить backend и socket-сервер:

```bash
docker compose exec gg-php_8.4 php artisan migrate
docker compose restart socket-server-nodejs
```

Основные feature-тесты находятся в `backend/tests/Feature/GuildActivityLogTest.php`. Они проверяют изоляцию по гильдии, пагинацию по 50, фильтры, observer-запись, авторизацию рулетки и внутренний аудит.
