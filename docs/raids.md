# Рейды: состав и набор

Страница `/guilds/{guildId}/raids` отображает рейды гильдии в виде дерева. Листовой рейд хранит собственный состав, а родительский объединяет информацию из всех дочерних рейдов.

## Просмотр состава

- У каждой карточки есть явная кнопка **«Открыть состав»**. Она открывает сетку участников листового рейда.
- У родительского рейда кнопка называется **«Участники»** и открывает отдельное окно.
- В окне родительского рейда пользователи сгруппированы по аккаунту. Для каждого персонажа показаны класс, теги и все дочерние рейды, в которых он состоит.
- Родительский рейд не хранит собственных участников и не может открывать набор.

## Открытие и закрытие набора

Управлять набором листового рейда могут:

- пользователь с правом гильдии `formirovat-reidy`;
- пользователь, которому принадлежит персонаж-лидер этого рейда.

В меню карточки доступны действия **«Открыть набор»** / **«Закрыть набор»**. Открытый набор обозначается бейджем **«Набор открыт»** и кнопкой **«Подать заявку»**.

## Подача заявки

Подать заявку может участник гильдии от принадлежащего ему персонажа. Если в гильдии у пользователя один персонаж, он выбирается автоматически; если несколько — открывается окно выбора.

Ограничения проверяются и интерфейсом, и API:

- набор должен быть открыт;
- заявка разрешена только в листовой рейд;
- персонаж должен принадлежать текущему пользователю и состоять в гильдии;
- персонаж ещё не должен состоять в выбранном рейде;
- пара `raid_id + character_id` уникальна: повторная заявка запрещена, пока предыдущая ожидает решения или принята; после отклонения её можно подать снова.

После успешной отправки на карточке появляется отметка **«Заявка подана»**, а лидер рейда получает in-app уведомление.

## Рассмотрение заявок

Лидер рейда и пользователи с правом `formirovat-reidy` видят пункт **«Заявки»** в меню карточки. Счётчик рядом показывает число заявок со статусом `pending`.

В окне заявок отображаются:

- ник персонажа;
- его классы;
- гильдейские и личные теги;
- кнопки **«Принять»** и **«Отклонить»**.

При принятии персонаж транзакционно добавляется в первую свободную ячейку сетки рейда, заявка получает статус `accepted`. При отклонении выставляется статус `rejected`. Повторное рассмотрение уже обработанной заявки запрещено. В обоих случаях владелец персонажа получает in-app уведомление со ссылкой на страницу рейдов. Сообщение содержит имя пользователя, который принял решение.

Уведомление отдельно сохраняет `game_id` и `guild_id`. API также возвращает названия игры и гильдии. В интерфейсе они отображаются рядом со временем одинаковым вспомогательным шрифтом: `Игра · Гильдия · время`. Это позволяет оставить основной текст уведомления коротким и при этом однозначно показать его источник в глобальной ленте.

Миграция контекста заполняет `game_id` и `guild_id` для существующих уведомлений по ссылке и удаляет из их сообщения старый текстовый префикс с игрой и гильдией.

## API

Все маршруты требуют авторизации и членства в гильдии.

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/api/v1/guilds/{guild}/raids` | Дерево, состояние набора, свои заявки и счётчики |
| GET | `/api/v1/guilds/{guild}/raids/{raid}` | Состав одного рейда |
| GET | `/api/v1/guilds/{guild}/raids/{raid}/descendant-users` | Пользователи и составы дочерних рейдов |
| PUT/PATCH | `/api/v1/guilds/{guild}/raids/{raid}/recruitment` | Открыть или закрыть набор |
| GET | `/api/v1/guilds/{guild}/raids/{raid}/applications` | Ожидающие заявки для управляющего |
| POST | `/api/v1/guilds/{guild}/raids/{raid}/applications` | Подать заявку (`character_id`) |
| POST | `/api/v1/guilds/{guild}/raids/{raid}/applications/{application}/accept` | Принять заявку |
| POST | `/api/v1/guilds/{guild}/raids/{raid}/applications/{application}/reject` | Отклонить заявку |

## Данные

- `raids.is_recruiting` — состояние набора.
- `raid_applications` — заявка, персонаж, статус, время и пользователь принятия решения.
- уникальный индекс `raid_applications(raid_id, character_id)` исключает дубли; при повторной подаче после отказа существующая запись возвращается в статус `pending`.
- `raid_members.accepted_at` и `raid_members.slot_index` заполняются при принятии.

Изменения состава и дерева транслируются через существующие события Socket.IO `raid:updated` и `raids-tree:updated`. In-app уведомления передаются клиенту стандартным `NotificationObserver`.
