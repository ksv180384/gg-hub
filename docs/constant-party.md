# Конст пати

## Назначение

Конст пати - постоянная группа персонажей на одном сервере. Функция нужна для организации стабильного состава, отдельного общения, учета общего хранилища и истории выдачи предметов участникам.

Пользователь создает КП от имени своего персонажа. Этот персонаж становится лидером группы.

## Навигация

В пользовательском меню на аватаре добавлен пункт `Мои КП`.

При наведении мыши отображается подсказка `Мои конст пати`.

Основные страницы:

| Страница | Назначение |
|---|---|
| `/my-constant-parties` | Список КП пользователя, активные приглашения и быстрый переход к группе |
| `/my-constant-parties/create` | Создание КП с выбором персонажа-лидера |
| `/constant-parties/:id` | Страница КП: участники, приглашения, чат, хранилище |

## Привязка к игре

Каждая КП хранит `game_id`, полученный от персонажа-лидера. Список КП, входящие приглашения, доступные лидеры и прямой просмотр фильтруются по игре, сайт которой сейчас открыт.

Основные API-запросы передают обязательный `game_id`:

```http
GET /api/v1/constant-parties?game_id={game}
GET /api/v1/constant-parties/{constant_party}?game_id={game}
POST /api/v1/constant-parties
```

При создании `game_id` в запросе должен совпадать с игрой выбранного персонажа-лидера. Попытка открыть КП другой игры в текущем игровом контексте возвращает `404`.
## Правила состава

У каждой КП есть название и лидер.

Ограничения:

| Правило | Описание |
|---|---|
| Один сервер | Все участники должны быть на том же сервере, что и лидер |
| Один активный состав | Один персонаж может состоять только в одной активной КП |
| Лидер обязателен | КП создается только с персонажем-лидером |
| Лидер управляет КП | Лидер может приглашать персонажей, отзывать приглашения и менять права хранилища |

## Смена сервера персонажа

При смене сервера персонажа применяется серверное правило:

| Сценарий | Поведение |
|---|---|
| Сервер меняет обычный участник КП | Персонаж исключается из КП |
| Сервер меняет лидер КП | Смена сервера блокируется, пока персонаж является лидером |
| После исключения | Участникам отправляется уведомление о выходе персонажа из состава |

Это сохраняет инвариант: все активные участники КП находятся на одном сервере.

## Объединение серверов

При административном объединении серверов КП целиком переносится на целевой сервер. Лидер, участники, ожидающие приглашения, права и банк сохраняются. Подробнее: [объединение серверов](server-merge.md).

## Приглашения

### Поиск персонажа

Приглашение отправляется не по ID персонажа, а через поисковую строку по нику.

Поиск работает во время ввода текста:

| Правило | Описание |
|---|---|
| Минимальная длина | Поиск запускается от 2 символов |
| Задержка | На фронтенде используется debounce 300 мс |
| Сервер | Возвращаются только персонажи на том же сервере, что и лидер КП |
| Исключения | Не возвращаются текущие участники КП и персонажи с активным pending-приглашением |

API:

```http
GET /api/v1/constant-parties/{constant_party}/invitations/candidates?query=ник
```

### Отправка приглашения

Лидер выбирает найденного персонажа и отправляет приглашение.

API:

```http
POST /api/v1/constant-parties/{constant_party}/invitations
```

После отправки владелец приглашенного персонажа получает уведомление о приглашении в КП.

### Принятие и отклонение

Приглашенный пользователь может принять или отклонить приглашение.

API:

```http
POST /api/v1/constant-parties/invitations/{invitation}/accept
POST /api/v1/constant-parties/invitations/{invitation}/decline
```

После принятия персонаж добавляется в состав КП. После отклонения приглашение получает статус `declined`.

В обоих случаях пользователь, который отправил приглашение, получает уведомление с результатом: согласие или отказ.

### Отзыв приглашения

Лидер может отозвать pending-приглашение.

API:

```http
POST /api/v1/constant-parties/{constant_party}/invitations/{invitation}/revoke
```

## Чат КП

У каждой КП есть собственный чат, доступный участникам группы.

API:

```http
GET /api/v1/constant-parties/{constant_party}/chat/messages
POST /api/v1/constant-parties/{constant_party}/chat/messages
```

В MVP чат работает через REST-запросы. Realtime-доставка сообщений может быть добавлена позже через существующую Socket.IO-инфраструктуру.

## Хранилище КП

У КП есть общее хранилище с историей выдачи предметов.

### Права

Участнику можно выдать право управления хранилищем через поле `can_manage_storage`.

Управлять хранилищем могут:

| Роль | Возможности |
|---|---|
| Лидер КП | Полное управление хранилищем и правами участников |
| Участник с `can_manage_storage` | Управление предметами и выдачами |
| Обычный участник | Просмотр хранилища и истории выдач |

### Тиры предметов

Тиры позволяют классифицировать предметы по ценности или приоритету.

API:

```http
POST /api/v1/constant-parties/{constant_party}/storage/tiers
PUT /api/v1/constant-parties/{constant_party}/storage/tiers/{tier}
DELETE /api/v1/constant-parties/{constant_party}/storage/tiers/{tier}
```

### Предметы

Предметы хранятся внутри КП и могут быть привязаны к тиру.

API:

```http
POST /api/v1/constant-parties/{constant_party}/storage/items
PUT /api/v1/constant-parties/{constant_party}/storage/items/{item}
DELETE /api/v1/constant-parties/{constant_party}/storage/items/{item}
```

### Выдачи

Каждая выдача фиксируется в истории: какой предмет, кому выдан, кто выдал, количество и комментарий.

API:

```http
POST /api/v1/constant-parties/{constant_party}/storage/grants
GET /api/v1/constant-parties/{constant_party}/storage/items/{item}/grants
```

### История участника

На вкладке состава участник выбирается нажатием на его ник. После выбора отображается история всех предметов, которые этот персонаж получил в КП: предмет, дата выдачи, причина и персонаж, выполнивший выдачу.

При выходе или исключении персонажа его активное членство удаляется, но связь с КП сохраняется в `constant_party_former_members`. Бывшие участники отображаются внизу состава приглушенным цветом, и их история выдач остается доступной. Если персонаж повторно вступил в ту же КП, пока он активен, запись не показывается среди бывших участников.

API:

```http
GET /api/v1/constant-parties/{constant_party}/storage/former-members
GET /api/v1/constant-parties/{constant_party}/storage/characters/{character}/grants
```

## Модель данных

Основные таблицы:

| Таблица | Назначение |
|---|---|
| `constant_parties` | КП: игра, название, лидер, локализация и сервер |
| `constant_party_members` | Участники КП и их права |
| `constant_party_former_members` | Бывшие участники КП и даты их выхода |
| `constant_party_invitations` | Приглашения персонажей в КП |
| `constant_party_chat_messages` | Сообщения чата КП |
| `constant_party_storage_item_tiers` | Тиры предметов хранилища |
| `constant_party_storage_items` | Предметы хранилища |
| `constant_party_storage_item_grants` | История выдачи предметов |

Для MariaDB у внешних ключей в миграции используются короткие имена ограничений, чтобы не упереться в лимит длины идентификатора.

## Тесты

Покрытие feature-тестами находится в:

```text
backend/tests/Feature/ConstantPartyTest.php
```

Проверяются основные сценарии:

| Сценарий | Описание |
|---|---|
| Создание КП | Пользователь создает КП своим персонажем |
| Ограничение сервера | Нельзя пригласить персонажа с другого сервера |
| Поиск кандидатов | Поиск возвращает только подходящих персонажей текущего сервера |
| Принятие приглашения | Персонаж входит в КП |
| Отклонение приглашения | Отправитель получает уведомление об отказе |
| Смена сервера | Участник исключается из КП при переходе на другой сервер |
| История бывшего участника | После выхода участник остается доступен для просмотра полученных предметов |
| Изоляция игр | Список, приглашения, создание и прямой просмотр ограничены выбранной игрой |

Запуск:

```bash
cd backend
php artisan test tests/Feature/ConstantPartyTest.php
```

## Ограничения MVP

| Ограничение | Возможное развитие |
|---|---|
| Чат работает через REST | Добавить realtime через Socket.IO |
| Права есть только для хранилища | Добавить расширенные роли КП |
| Поиск кандидатов ограничен ником | Добавить фильтры по классу, роли или уровню |
| История выдач фиксирует факт выдачи | Добавить статусы, откат выдачи или аудит изменений |
